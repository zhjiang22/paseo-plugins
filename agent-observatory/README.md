# Agent 观测台（Agent Observatory）

2.18.1（适配 Paseo 0.14：未载入的会话不再被反复载入，定时/心跳提示算一轮的开始）。2.18.0（原地打转、可能卡住，上级等子 Agent 交差再提醒）。2.15.1（分片服务端首次读取才分段）：连接时只加载注册信息与常驻角标，第一次打开页面、面板或角标弹层时再加载界面，弹层里的就地审批和快捷回复跟着弹层一起加载。`index.client.tsx` 是由 Paseo 直接编译的普通常驻桩源码，体积预算为 48 KiB（2.17 加入提示音后）；入口保持 `export default function`。所有原有页面与命令保留；仍要求 Paseo ≥0.11.1。

界面分片逐片拉取，每个 RPC 响应不超过 128 KiB。同一次 App 运行期内重连复用按 hash 缓存的文本；新连接单独求值，不复用旧连接的状态。首次打开显示加载提示，失败可重试，接口版本不一致时提示重新连接。应用进程关闭后缓存清空；首次打开的分片仍需传输。

「需要处理」与定时运行失败计数始终可见，前台每 20 秒读一次小摘要，后台停止；读取失败或数据超过 90 秒就隐藏旧数字。角标读取时上报设备时区，和页面、弹层共用同一份读数：在详情里点「知道了」「标记已读」，或在弹层里处理审批、发出快捷回复后，角标马上重读。打包时运行仓库根目录 `npm run build`，并提交 `server/generated`、`shared/generated`；`npm run check` 会重新构建并拒绝陈旧产物，同时检查常驻桩的默认 Hermes 编译、无 `class`、interop 补丁、入口导出和体积预算。

从项目和 worktree 看任务，从最新回复看结果。一个面向 Paseo 0.11 的原生可观测插件，支持手机、桌面和深浅主题。界面支持英文、简体中文和用户自定义语言，默认跟随系统。

## Languages / 语言

内置英文与简体中文，默认「跟随系统」；设备语言尚无翻译时显示英文。在 **Paseo 设置 → 插件 → Agent 观测台 → 语言**，或看板的 **观测设置** 中选择语言，已打开的界面会随之更新。新的智能分析按当前语言回答，已保存的报告保留原文。

自定义语言目录为 `~/.paseo/plugin-data/agent-observatory/locales/`；自定义 daemon home 时是 `$PASEO_HOME/plugin-data/agent-observatory/locales/`。从目录里的 `templates/en.json` 或 `templates/zh-CN.json` 复制一份，放到同一目录并命名为语言代码，例如 `ko.json`。把 `$meta.name` 改成该语言自己的名字，翻译各条消息，保留原有 `{placeholder}`。单复数使用 CLDR 的 `one`、`other` 等形式，必须有 `other`。缺少或无效的条目显示英文；语言设置会显示翻译覆盖率与文件问题，修改后点「重新读取」。插件更新时会刷新模板。文件名为 `en.json` 或 `zh-CN.json` 时，只覆盖文件中写出的条目。

贡献内置语言：提交 PR，增加 `shared/locales/<code>.json`，并在 `server/locales.ts` 中注册一行；消息 ID 与占位符需与英文目录一致。

## 界面（2.6）

- **第一行就是会话**：顶部一行切换「会话 / 看板 / Token / 明细 / 横评 / 事件 / 分析」，选中的视图是一枚渐变胶囊，手机上其余视图只显示彩色图标；旁边是搜索和「···」。不常用的操作都在「···」里：已归档会话、列表/树状、排序、展开全部子 Agent、导出快照、刷新。
- **快捷范围**：「需要处理」（待审批、提问、计划待批、没看过的异常、额度用尽和没收尾的轮次、完成未读、还没看的待回复，已稍后处理的除外；子 Agent 的完成结果默认不算，见下文）、「执行中」（含启动中和后台执行中）、「未读」、「待回复」（含在问你问题、等你选的），后面是项目、时间范围和「筛选」。已生效的条件显示为可移除标签，保存的视图可以一键切换。
- **按处理优先级分组**：按「需要处理 → 执行中 → 最近」分组，子 Agent 树随顶层会话一起移动；改为按最近活动排序时不分组。子 Agent 的未读数显示在折叠开关上。
- **状态一眼可辨**：每种状态有自己的颜色、图标和文字——执行中蓝色转圈并按秒计时，待审批琥珀色举手并向外扩散，提问紫色问号，计划待批琥珀色清单，异常红叉，额度用尽橙色电池，空轮和未收尾琥珀色虚线圈，未读粉色信封，待回复紫色对话气泡，已完成绿勾，稍后靛蓝闹钟；空闲、未载入（Paseo 释放了空闲会话，发消息时自动恢复）、已取消是灰色图标。除执行中和未载入外，每行右侧都有状态标签，「图例」（也在「···」里）逐一解释这些标记。
- **后台执行中也算执行中**：Claude Code 等会把任务交给后台子任务，自己这一轮先结束，Paseo 显示「1 working」。这样的会话仍算执行中：行内是蓝色「后台 · 任务」标签，知道子任务何时开始时右侧显示「后台 1:35」，详情顶部写明还有几个子任务在跑，可直接打开「子任务」。它在后台干活期间不算未读、待回复或需要处理。服务端跟随宿主的子任务事件，不轮询每个会话；只查询已在宿主里加载的会话，因为查询未加载的会话会让宿主重新载入它。看板上的执行中也这样计算。
- **待回复 = Agent 在问你**：只有一轮结束时的最后一条回复把下一步交给你（要不要继续、选哪个方案、需要你确认或发来输出等）才算待回复，你发出下一条消息就解除；还没看的提问同时算「需要处理」。判断在服务端做，只保存「是否在问」这个结果，不保存回复内容。插件没看到结束的轮次（排队消息、插件重载时结束）：会话还在宿主里加载着就在一分钟内补读时间线结尾，否则在你打开它时补上（后台从不读取未加载的会话，免得宿主把它重新载入）；仍不知道结果的已停止会话显示为「空闲」。看板上的「待回复」数与会话列表一致。
- **颜色鲜明**：kit v3 调色板在深色主题下是更亮的霓虹色，新增天蓝、青柠、洋红；六个视图各有渐变色（会话蓝、看板粉、明细紫、横评青、事件橙、分析绿），详情里的结果、时间线、子任务、诊断、分析也各有颜色。每个项目有固定颜色（与其他插件一致），会话行、详情、项目列表和排行里都用它标识。
- **会动的地方只在有事发生时**：会话状态变化时，这一行用新状态的颜色闪一下；新事件从事件流顶部滑入；详情里执行中的会话顶部有一条来回扫动的进度条；工具栏的「实时」圆点在连接正常时向外扩散；数据洞察的柱子在打开时长出来。网页端用 CSS 动画、手机用原生动画驱动，切到后台即暂停；系统开启「减少动态效果」时全部静止，状态仍靠形状、颜色和文字区分。
- **行内提醒**：待审批（带请求数）、重复失败、异常、未读、长时间无状态更新直接标在会话行右侧的彩色标签里，按这个优先级只显示一个；已稍后处理的未读显示为「稍后」。
- **详情**：宽屏（≥760）在右侧分栏显示，手机推入整页，主要操作固定在底部。主按钮是「打开会话」（有待审批时为「处理审批」，在提问时为「去回答」，计划待批时为「查看计划」，已归档为「恢复会话」），未读时旁边是「已读并看下一个」，待回复时是「标记已读」，异常和停下的轮次是「知道了」，已读后可「归档」，其余在「···」。工具类审批在「结果」页可以直接批准或拒绝（见下文「就地审批」）。恢复会话时详情顶部显示当前步骤（例如「正在重建关联的 worktree，可能要一两分钟」），不受宿主 30 秒请求上限影响。
- **执行详情面板**：会话里的「执行详情」（`/observe`、Command Center「观测当前 agent」）只看这一个 Agent，已归档的也能看；「子任务」页打开时才读 Agent 目录，「··· → 在观测台中查看」打开完整页面并选中它。
- **说明按需查看**：口径说明放在各处的 ⓘ 里（事件记录、数据洞察、自动分析、诊断各节）；复制、已读、稍后处理等确认改为轻提示，失败显示一行横幅并可重试。

## 需要处理、停下原因与续跑（2.13、2.14）

- **侧栏角标**：侧栏「Agent 观测台」旁显示需要处理的数量，琥珀色；有异常或额度用尽时变红（不只看弹层里的前 8 条），有审批、提问、计划在等时外圈扩散。点数字弹出列表（手机上是底部弹层），等得最久的在前，最多 8 条，每条一句话原因，点一条直接打开那个 Agent；「在观测台中查看全部」打开「需要处理」筛选。服务端还没读完目录、读取失败（包括服务端自己读目录失败）或数字已过时不显示数字，弹层写「暂时读不到」；目录太大时显示「N+」。计数在服务端用和页面完全相同的规则算出。「定时运行」旁显示近 24 小时失败的次数。
- **一句话原因**：需要处理的会话下面多一行，说明它要你做什么，不调用模型——「问你：要合并到 main 吗？（是 / 否）」「计划待批：拆分存储层」「要执行：npm test（共 2 项）」「出错：<错误第一行>」「额度用尽 · 05:00 恢复」。待回复和未读结果用宿主自己的提醒文字（只在内存里，最多 160 字，先遮蔽凭据）。
- **一轮为什么停下**：额度或限流用尽（读出恢复时间，按本机时区显示）、空轮（没有任何输出）、可能未收尾（停在工具调用之后）都单独标出，不再显示成「已完成」或「空闲」。只看失败原因和结尾的短句，不扫普通回复，也不保存文字。Provider 自动重试（429、过载）后照常完成的一轮不算额度用尽；`/compact` 等本地命令和上下文压缩不算空轮。收尾回复里只是写了限流或额度功能的，不算额度用尽：点名你自己额度的提示（You've hit your … limit、5-hour limit reached 等）照旧识别，其余写法要求整条回复很短并且读得出恢复时间。提示里只有钟点、没写时区（resets 5am）时，按设备时区解析并写「约 05:00 恢复（推测）」；设备时区由侧栏角标等读取时上报。宿主关闭（卸载）Agent 时，没结束的那一轮记为可能未收尾（「宿主关闭会话时这一轮还没结束」），同样计入需要处理。
- **停下没看过就计入**：额度用尽、空轮、可能未收尾，不管这一轮以「已完成」还是「空闲」结束，没看过就计入需要处理和侧栏角标；子 Agent 也计入，不受「子 Agent 完成也计入需要处理」开关影响，也不能「稍后处理」。宿主为这一轮发过提醒的，在 Paseo 里打开会话，或在这里点「知道了」，就算看过；宿主关闭会话时还没结束的那一轮，宿主不发提醒，只有在观测台点「知道了」才算看过（记录在观测文件里，重启后仍有效）。会话没有载入时（daemon 重启后全是这样），「知道了」「标记已读」都不为清提醒去载入会话（ACP Agent 也载入不了）：观测台核对宿主的提醒令牌后自己记下，Paseo 自己的提醒在下次载入会话时清除。看过之后行内仍显示停下的原因，但不再计入。
- **恢复后续跑**：额度用尽的会话详情顶部有「恢复后续跑 · 05:02 唤醒」。确认框写明唤醒时间（恢复后 2 分钟，按本机时区；推测的恢复时间会写明）和到点要发的续跑提示。读不出恢复时间时可以选 1 / 3 / 5 小时后；主机的额度读数能对上这个 Provider 底座（daemon 配置的 `extends`）的唯一账号时，还可以选「按额度窗口：05:00 重置」。确认后建一个只运行一次的心跳（按 UTC 时刻，秋季回拨那一小时也不会提前）。只有对得上这次运行的证据才算已续跑：宿主记录这次运行成功或停在审批上，或者 Provider 自己的本机会话日志里有带这次心跳和运行编号的续跑提示（Claude Code、Codex、Pi 会把发出的提示写进去）；在那之前卡片显示「正在唤醒」。看到它开始了一轮不算数：子 Agent 完成通知这类系统提示也会开一轮。到点时 Agent 正忙（包括你自己发消息开的那一轮，这时算「你已接着做」）、或那一分钟宿主不在线，观测台会在原定时刻起 6 小时内自动再试；「正忙」「载入超时」只认宿主自己的完整报错，而且先看这次运行的证据：续跑提示送进去之后宿主把 Agent 最后一句回复当作报错，这句话可能和宿主的报错一字不差，所以只有确认这次的续跑提示没有发出时才自动再试，要同时满足：这次运行结束之后，观测台平时的扫描（每 30 秒一次）已经把日志目录完整扫过一遍（之后新发现的日志目录也要扫过），没有因为数量上限被截断，这个会话的日志所在的目录也都读得出来，在这之前不下结论，下一次核对再看；运行开始以后，这个会话的日志没有消失、没有被换成符号链接或另一份文件、没有被截短，所在的日志目录也没有消失或读不出来；每份都从头读到尾（最多 128 MB），读的过程中文件没有变化（正在追加就稍后重读，最多 3 次），而且都没有这次的续跑提示。Grok、ACP 这类观测台读不到会话日志的 Provider，日志被截断、丢失、打不开、一直在变或被改写过，或者 6 小时窗口内一直等不到完整的扫描，即使报错一字不差也显示「未能确认续跑」。宿主报错或重启打断、又证明不了送达时，显示「未能确认续跑」，不自动重发，请先看会话。停下之后你已经自己给它发过消息，续跑自动取消。每个 Agent Paseo「计划」里改过的续跑心跳（换了提示、次数、目标或名字），观测台不再管理：不当续跑核对、不重试、不删除，卡片显示「心跳被改过」；只改了时间的（推后或提前，改成每两小时一次这类仍包含原来时刻的规则也一样）仍是续跑，观测台按你改的时间等，不会当成错过而删掉重建：它比的是心跳的定时规则和建立（或接管）时是否一样，规则没变而时间被推后的，才是宿主重启时顺延，照旧自动再试；改到 6 小时窗口之外也照样等，只是那时运行失败不再自动重试，心跳到期（原定时刻后 6 小时）前还没运行就记为「未能续跑」。宿主答复丢失时（插件会话重连、超时）：安排续跑时不知道心跳建好没有，就记成一条「正在核对」的续跑，回复写明观测台会在下一分钟核对，不当场去找，也不自动补建；这时再点会回「已记下 HH:MM 分钟仍一条都没有，或者有不止一条，也记「未能确认续跑」，请你到「计划」里看：没有就「重新安排」，多出来的删掉；读列表一直失败时会一直显示「正在核对」，读到了再下结论。「重新安排」时，那条后来写进了宿主、还在等着没运行过，就直接接管它，不会再建；已经在跑或跑完的，按你要的新时间另建一条。重试那次的答复丢了也这样认，只在一条都没有时、唤醒前两分钟补建，不止一条不补。取消「正在核对」的续跑：找到唯一一条就删掉；分不清时不取消，请你到「计划」里核实；一条都没有时停止核对和补建，并提醒你之后在「计划」里看到它就删掉。取消时先删心跳、删成了再记已取消；删除失败就回复「取消续跑失败」，记录不变。自己删掉的心跳其实已经删掉（答复丢了但再读一次已经不在），就照常往下走，不会当成你在 Paseo 里删的；删除的答复和紧接着的那次读取都丢了时，下一次读到它不在，会当成你在「计划」里删的，记「已取消」、不再重试（已知限制）。宿主（0.11.1）没有幂等创建，也没有条件删除，观测台只能把窗口缩小：宿主写盘超过 2 分钟时，第一次的心跳可能在记成「未能确认」之后才落地，到点照样唤醒；重试在唤醒前两分钟补建，那时宿主还没写完的那条落地后会多一条；观测台最后一次读到心跳之后你再在「计划」里改它，观测台仍可能按读到的样子删掉它。卡片上显示真实状态（已安排 / 正在核对 / 正忙稍后再试 / 正在唤醒 / 已续跑 / 未能确认续跑 / 未能续跑 / 你已接着做 / 心跳被改过 / 已取消），可以直接「取消续跑」或「重新安排」；观测台正忙、这次请求等得太久时，取消和安排都不做任何改动，提示再试一次。不确认就什么都不会发生。
- **交给另一个 Provider**：额度用尽时也可以「交给另一个 Provider…」：在同一工作区用你选的 Profile 新建 Agent。第一条消息不贴整段对话，而是让新 Agent 用 `paseo inspect` / `paseo logs` 自己读原会话、看工作区改动后接着做（发送前可以改）；同一额度来源的 Profile 置灰提示；原会话还在等续跑时可以顺手取消。
- **会话行上的标记**：执行中的会话显示待办进度「3/7 · 正在跑测试」；上下文用到 85% 显示琥珀色「上下文 87%」，95% 变红；回复提到的合并请求 / 拉取请求显示为「!42」/「#17」，点一下在浏览器打开；被心跳指向的会话显示粉色「22:35 唤醒」，详情顶部有心跳卡片。
- **已读、知道了、稍后处理**：待回复可以「标记已读」或「稍后处理」（之后又被提示、再次提问时会重新出现）；异常看过后点「知道了」，之后仍是红色，但不再计入需要处理；空轮和可能未收尾同样可以「知道了」，不会因此变成「已完成」。连续几轮都没看时（包括心跳接着跑的几轮：宿主既不更新最后发言时间，提醒也停在第一轮），「标记已读」记的是最新一轮的完成时间（服务端核实过），归档、重启后仍是已读；只有结果页显示的正是这一轮的结果时才能标记，上一轮的结果不会被当成新一轮已读。「稍后处理」和快捷回复也按轮次：对上一轮的稍后处理不会压住下一轮，之后又跑过一轮就不再发上一轮的快捷回复。待回复的「标记已读」带上页面显示的那一轮，服务端核对仍是最新一轮才清提醒或记回执，停在上一轮提问的页面不会把新一轮的提问标成已读。在审批里选「拒绝并中断」后，被中断的那一轮在 10 秒内失败记为取消。
- **就地审批**：待审批的工具请求（命令、文件改动、MCP 调用等）在弹层里点「在这里审批」展开，在详情「结果」页直接显示。能看到要执行的完整命令和全部参数、涉及的文件或搜索内容和工作目录（请求没写目录时显示 Agent 的工作目录并注明）；「展开完整内容」显示原文，参数全部列出，每项最多 64 KB，超出时写明截在多少字（参数还会写明共几项、后几项没有完整显示，按每个参数结束的位置数，参数值里的换行不算新的一项），宿主自己截断的差异也会注明。Provider 给了选项就原样显示它的选项（例如 Allow / Always Allow / Reject），按你选的原样回复；没给就是「批准」「拒绝」；「拒绝并中断」会拒绝并停下这一轮（OpenCode、omp 不支持随拒绝中断，不提供）。会一直生效的选项是琥珀色，需要再点一次「确定」。处理前会确认这条请求还在等，处理后会确认宿主已经收到，没收到会提示。不做批量批准，也不自动批准；提问和计划请到会话里回答或批准。
- **快捷回复**：最新回复在征求继续（「要我继续吗？」「要不要我顺手把 README 也改了？」"Shall I …?"）时，详情里显示「继续，按你说的做」「先别动」；在宣布下一步却结束了这一轮（「接下来我会…」"Next, I'll …"）时显示「继续做完」「先别动」（带前提条件的下一步，例如「CI 通过后合并」，不显示）。发给 Agent 的就是按钮上这句话（句末加句号）。快捷回复只回答它出现时的那一轮：Agent 已经开始新的一轮就不发，并告诉你这条不再适用；清提醒之后、发出之前还会再核对一次轮次，读不到最新轮次时这次不发，请刷新后再试。这一轮也随消息交给服务端：同一轮只发出一条快捷回复（不管哪个按钮、哪台设备；另一台先答了，这里会告诉你答的是哪一条），服务端发送前、排队的回复送出前都再按插件看到的轮次核对一次，观测台自己的记录核实不了这一轮（保存的事件历史损坏后记录是空的、只有更早的一轮、记录正在报错）时不发：立即发送提示稍后再试，排队的留在待确认；「继续」先清这一轮的提醒时也带上这一轮，已经是新的一轮就不清，新提问仍然计入需要处理。侧栏弹层只在能引出它回答的那句话时才给快捷回复（按钮上方写「它问：「…」」）；这句话只在内存里，插件重载后要到详情里回复。只看句式、不调模型、不保存回复内容；选择题、要你提供信息、问你意见的回复不显示，子 Agent 也不显示。
- **子 Agent 的结果**：子 Agent 完成默认不计入需要处理，上级 Agent 已经拿到结果；它们的未读仍显示在上级那一行。在「··· → 观测设置」里可以改为计入（对这台主机的所有页面和侧栏角标生效）。子 Agent 出错、等审批、提问照常计入。
- **归档已读完成**：「··· → 归档已读完成（N）」第一次点只把要归档的行标红，再点「确认归档」才执行；只包含结果已经看过、整条上下级链都没有在运行、没有心跳（包括暂停的）或额度等着它的会话。Paseo 归档上级时会连带归档同一工作区里它派出的子 Agent，并结束它们的心跳，所以子 Agent（以及更下层）也都要已读、已完成、没有停因、不在运行、没有心跳，上级才会列入；会话较多、只加载了一部分时这一项变灰。心跳要完整读到才提供这一项：定时任务目录或文件读不出来、数量超过读取上限时，这一项变灰并写明原因；确认时会再读一次心跳，这期间新建了心跳的会话会留下。
- **发送账本**：快捷回复和「发给这个 Agent」都交给插件服务端的发送账本发出（和「拾页 · 项目手记」等插件共用同一套）。服务端发送前按 Agent 当时的状态再判断一次，你同意的不再覆盖就不发、重新问你。要打断回合或取消审批时，确认有三个选择：「中断并发送」（有审批时是「仍然发送」）、「等这一轮结束再发」（有审批时是「等审批处理完再发」）、「取消」；排队的消息在这一轮结束、没有待审批时自动发出，页面关着也照发。同一条消息同一时间只有一条在路上：别处已经排队或在等你确认时，这里的按钮锁住，旁边那一行可以「仍然发送」或「取消排队」。回包丢了再点一次，按原编号去问，不会发两份。选「等这一轮结束再发」后按账本实际返回的状态提示：只有排队中才说会自动发送；待确认的那一行写明原因、给出「仍然发送」；可能已送达时先请你看会话；已取消、已过期、未发送各有说明。
- **发给这个 Agent**：智能分析里的「发给这个 Agent」不会再打断正在运行的那一轮。支持插话的 Provider（Claude Code、Codex 等，以及 daemon 配置里 `extends` 它们的自定义 Provider）插进当前回合；斜杠命令只插话进 Claude 系，其他 Provider 运行中要先确认。不支持插话、或者正在等审批时（发送会取消这次审批），先告诉你会中断什么并要你确认；确认绑定到具体的待审批请求，请求换了、轮次或状态变了都会再问一次。每条消息只用一个消息标识，重试沿用同一标识，宿主保证最多送达一次；宿主说「可能已经送达」时不再重发，先请你看会话。没有打开的会话（daemon 重启后都是这样）照常发送，Paseo 会先载入它；已归档的不发。

## 提醒：提示音、侧栏标签、缓存倒计时、定时发送（2.17）

- **提示音**（参考 Herald 的想法）：「需要处理」多出新条目时响一声，提问、待审批与计划待批、额度用尽、失败（含空轮和未收尾）各有音色，完成未读和待回复默认不响。新安装默认关闭，在「··· → 观测设置」或 Paseo 设置里这个插件的设置中打开。只在 Paseo 开在前台时响；每个事件每台设备只响一次，同一个 Agent 的同一轮 15 秒内只响一次；子 Agent 默认不响。免打扰时段按每台设备自己的时区，开始晚于结束表示跨夜。「这台设备静音」只影响这台设备：网页端和桌面端记在浏览器里；手机 App 没有可用的存储，只在这次打开 App 期间有效。声音由插件现场合成（16 kHz WAV，每种几 KB，不带音频文件），经宿主的 `playAudio` 播放；网页端第一次响之前，浏览器要求先在页面上点一下（点「试听」也行）。提示音跟着侧栏角标每 20 秒的读数走，不另外请求。
- **侧栏标签**（参考 sidebar-organizer 的想法）：打开「把需要处理写成侧栏标签」后，观测台把每个工作区最要紧的原因（待审批、提问、计划待批、出错、额度用尽、空轮、未收尾、待回复、未读）写成 Paseo 自己的工作区标签，颜色和观测台一致，原因解除就摘掉；还可以让等你的工作区自动置顶，处理完取消。只增删观测台自己加的标签和置顶（记在 `sidebar-labels.json` 里，插件重载后也记得）：你的标签不动、排在前面（被挤到你的标签前面时，下一次改写这个工作区时放回后面）；你摘掉观测台的标签，同一个原因不会再贴；你自己置顶的，或者摘掉后又置顶的，观测台不取消。原因变了才写：变化后 2.5 秒合并写一次，一次最多 12 个工作区，另外每分钟核对一次。标签用观测台当时的语言；只换语言不重写，等原因变化时换成新语言，旧语言的标签在没有工作区使用时从标签列表里删掉。关掉开关时清掉观测台加的标签和置顶，以及它新建、没有工作区在用的标签；卸载插件前请先关掉。新安装默认关闭；宿主不支持时显示「此 Paseo 版本不支持工作区标签」。写标签走插件现有的宿主会话（`workspace.label.assignment.set`、`workspace.pin.set`，Paseo 0.11.1 的插件 API 没有这两项）。宿主没有回应一次写入时（会话重连、超时），这次写入可能已经生效：标签照样记为观测台的，下一轮看宿主上有没有；置顶只在宿主确认之后才算观测台的，没有回应的那次置顶不认领（宁可漏掉，也不把你的置顶当成观测台的），原因解除或关掉同步时不会自动取消，需要时请手动取消。记录文件写不进时（磁盘满、不可写），不再新增标签和置顶，设置页的状态写明错误码。
- **提示缓存倒计时**（改编自 cache-clock，MIT）：基于 Claude 的会话（按 daemon 配置里的 `extends` 判断，不看 Provider ID）在会话行、需要处理弹层和详情顶部显示「缓存 4 分钟」。观测台读这个会话自己的 Claude Code 日志（含自定义 `CLAUDE_CONFIG_DIR`），按最后一次请求写缓存用的 TTL（5 分钟或 1 小时）算出到期时刻；压缩上下文或换了模型后显示灰色「缓存已冷」。最后 1 分钟（1 小时缓存是最后 5 分钟）变成琥珀色并呼吸，最后一分钟按秒倒数。服务端只给到期时刻（显示时每 30 秒读一次，带版本号；每份日志只读末尾最多 4 MB），设备自己倒数，不按秒请求；读不出来的会话不显示，会话行只在需要你处理时显示已冷的缓存。
- **定时发送**（参考 Defer 的想法）：快捷回复和「发给这个 Agent」旁边的「定时发…」：30 分钟后、1 小时后、3 小时后，或者指定哪天几点（按这台设备的时间，存成 UTC，最多 7 天后）。到点之前不发；到点之后和「等这一轮结束再发」一样，按 Agent 当时的状态再核对，空闲、没有待审批时发出，同一条只发一份；到点后最多再等一天。定时消息列在详情的「定时消息」和需要处理弹层里，可以「立即发送」（马上发，「最多等一天」从这一刻重新算）或「取消排队」，送达后消失。排好之后你再和这个 Agent 说话，到点时会先问你还要不要发，挂起说明写明这是定时消息。消息存在服务端的发送账本里，页面关着也照发；插件重载、daemon 重启后消息不丢，但要等任意一台设备打开 Paseo 或任意一个 Agent 有动静、观测台拿到宿主接口后才恢复计时，重启后没有设备连上时会迟发（到点后最多等一天）。选时间的地方也写着这两点。

## 原地打转、可能卡住、等子 Agent 交差（2.18）

- **原地打转**（参考 Cindy 的循环检测）：执行中的会话，观测台读待办进度时顺带看这一轮最近 80 行里的工具调用。同一个调用（参数和结果都一样）连着 4 次；最近 12 次调用里只有 2 种来回切换，或 16 次里不超过 4 种轮着来；同一个工具连着 3 次碰到同一类参数错误（要替换的文字找不到、匹配到多处、新旧内容一样、缺必填参数），都算打转。只看 30 秒内接连发生的调用：隔 30 秒以上算在等东西（CI、慢命令），等后台任务、`sleep`、看日志末尾这类轮询一律不算；但同样的调用连续 30 次，或者同样的结果持续一小时以上，再慢也算。
- **可能卡住**：这一轮最近几行 10 分钟没有任何变化（还有工具调用在跑时放宽到 45 分钟；子 Agent 工具的日志在增长也算有变化）。它派出的子 Agent 或后台 Agent 还在干活时是在等它们，不算卡住，从它们停下才开始计时。
- 两种都在会话行写一句原因（「疑似原地打转：Read 连续 4 次结果都一样」「可能卡住：npm test 已经跑了 47 分钟」），计入「需要处理」和侧栏角标（打转橙色、卡住琥珀色，开了提示音时按失败的音色响，侧栏标签同色），详情顶部的卡片列出最近几次调用（先遮蔽凭据），可以「打开会话」或「知道了」。点「知道了」之后仍然显示，但不再计入；换了一种打转方式、或者到了下一轮会重新计入。只是提醒，不会替你中断 Agent。
- 不调模型、不读 Provider 日志，结果只在内存里。只读这个插件进程见过在跑的 Agent（读没载入的会话会把它载入），所以要有页面开着或侧栏角标在读（前台每 20 秒一次）才会发现。
- **等子 Agent 交差再提醒**：上级 Agent 这一轮结束了，但它派出的子 Agent（含更下层）还在跑、等审批或在提问时，上级行照旧显示执行中、「后台 N 个子任务」，完成提醒先压住，子 Agent 都停下后才算未读结果。子 Agent 等你批准、在问你、出错，照常单独计入。彩色活动行 0.10 的「子 Agent 实时动态」卡片同时写出「等你批准」「在问你」，出错时显示错误第一行。

## 会话现在默认看结果

- **最初输入固定展示**：单独读取真实会话起点，长输入可以展开；无法证明原始起点时标出「起点待确认」。
- **Agent 最新回复优先**：首屏展示输出，代码块、复制、测试证据和产物入口均可用。确认本轮已完成时标为「本轮结果」；否则最新回复不等同于最终完成证明。
- **过程按需查看**：切到执行时间线、子任务、诊断和智能分析；已加载历史、展开状态与阅读位置保留。
- **在时间线里查找**：时间线页的放大镜打开查找栏，只查已经加载的记录（写明「已加载 N 条」，更早的记录可以先读进来），显示「3 / 12」并可上下跳转；不分大小写和全角半角，支持多个词和引号短语，在消息和工具的命令、输入、输出里找。命中标成琥珀色，当前这处所在行加蓝框，折叠的内容会自动展开；同一条长输出里按下一处，会滚到命中的那一行。查找只在本机内存里进行。
- **原生子任务同样结果优先**：固定输入、最新回复、独立时间线，保持只读观察。

## 连续处理未读结果

「未读」（旧版称「待收菜」）列出完成但还没读的结果，包含托管子 Agent，不受普通时间范围隐藏。已读状态和完成状态分别表达。

- 「已读并看下一个」连续处理当前队列，确认的是当前显示的结果版本。
- 「稍后处理」延后当前结果 1 小时，新的完成结果仍会立即提醒。
- 浏览详情不自动清除未读；显式标为已读或在原生会话阅读后同步。
- 已读会话可以归档，原 Agent ID 与上下文保留。
- provider 内部子任务没有原生阅读元数据时，不伪造已读状态。

## 项目、worktree 与历史

普通观测台**只展示未归档会话**；已归档会话有独立侧栏页面。两页均能按项目、worktree、分支、状态、provider、工作区与时间查找。默认最近 7 天，可切换 24 小时、30 天或全部时间。

项目显示真实项目名称；worktree 名称来自 checkout 根目录，和工作区自定义标题区分。主工作区、本地目录分别标识。归档时间不会被当作新的执行时间。

视图自动按主机/页面/工作区保存（包括「需要处理」范围），也可以在「筛选」里命名保存常用筛选。搜索词只留在当前设备、本次打开期间，不会同步到其他设备（命名保存的视图会带上搜索词）。进入归档再回来，保留原有视图和搜索词。筛选在独立弹层中滚动，矮桌面窗口不会挤没列表。

## 看板、明细与横评（2.5）

参考 ai-usage-tracker、TokenTracker、ccmap、claude-usage-tracker 等开源项目的做法，按你所在时区统计 7 / 30 / 90 天：

- **看板**：渐变头卡（今天的轮次与工作时长、连续天数、等级，以及可点的 执行中 / 待审批 / 未读 / 待回复，直接跳到对应会话；这几个数直接用页面的实时目录、按会话列表同样的规则计算，未读不含稍后处理；旁边是最紧张的一个额度窗口）；8 个指标卡（会话、轮次、成功率、工作时长、并行时长、工具调用、代码行、审批），带环比和迷你柱；年度活跃日历；18 枚成长徽章与等级；每日趋势（7 日均线 + 按星期基线预测未来 7 天）；高光时刻（最长一轮、最忙一天、并发峰值、最能聊的会话、高峰时段）；星期 × 小时活跃时段；模型阵容环形图。
- **明细**：模型、厂商、Harness、项目四个维度，可按轮次 / 会话 / 时长 / 工具 / 代码排序；前三名领奖台、占比条，每行有成功率、平均每轮、工具/轮、新增/删除行数和上下文占用。「工具」看工具类型构成与常用工具及失败率；「观测」按本机时区显示 7×24 小时活动热力图、每日结果和用量快照。
- **横评**：任选两个模型、Harness 或厂商对决：比分、六维能力雷达（产出、速度、稳定、自主、省心、活跃）、称号（更稳、更快、更高产、工具更稳、更省心、更勤快）和「产出 / 效率 / 质量 / 投入」四组对比条；可交换左右或分别更换。

口径：所有按天的数字都按设备的时区（含夏令时切换）归到本地日期：统计按 UTC 小时保存，读取时按设备时区换算，晚上的轮次在任何时区都算当天。「明细 → 观测」和 Token 页同样按 UTC 小时保存、按设备时区换算：夏令时回拨那天重复的一小时合计显示，拨快跳过的一小时标为不存在；取不到设备时区时按 UTC 并标明。会话数来自 Paseo 全部会话（含已归档），按创建时间计入本地日期；轮次、时长、并发从插件开始观测时起累计；消息、工具调用和代码行数只统计每轮新增的时间线内容，代码行数按编辑工具的 diff 估算，不是 git 提交统计。各页 ⓘ 里有同样的说明。

- **今日与实时**：今天用了多少 token、实时输出速率（tok/s），以及正在输出的会话各自的速率；执行中的会话行也会显示速率。
- **实时流速**：最近 30 / 60 分钟每 10 秒一根柱子，每次调用的输出平摊到它的响应时间里；点任意一分钟看当时的速率。
- **统计**：总量、输出、缓存读取、缓存写入、新输入、缓存命中率、输出速率（P50 / P90）、调用次数，都带环比；每日趋势可以看总量、去掉缓存读取后的「非缓存」、输出和速率；按模型、Provider、Harness、项目拆分；最耗 Token 的会话可以直接打开。
- **Provider 用量**：按会话 ID 找到对应的 Paseo 会话，再按它的 Provider 汇总，几个自定义 Provider 共用同一个日志目录也能分开；找不到对应 Paseo 会话的日志（终端里直接运行的、会话已删除的）单列为「未关联会话」；日志目录只属于一个自定义 Provider（它自己的配置目录）时，那里没有对应会话的日志也算这个 Provider。Codex 派出的子 Agent 线程算在派出它的会话里。系统临时目录里的一次性会话在「项目用量」里合成一项「临时目录」。
- **额度**：页面顶部列出宿主用量接口（`providers.listUsage()`，和侧栏 Usage 同一来源）里每个账号的额度窗口；插件不读任何凭据，也不直接访问厂商接口。进度条上的竖线是节奏刻度，用量超过它时变红；5 小时这类一天以内的窗口按最近 30 分钟以上的速度预测几点用完（只在早于重置时提示），每周窗口按本周平均节奏外推到重置时（本周过去不到十分之一时不外推）；过了重置时刻显示「已重置，等新读数」，读取失败时保留上次的读数并标出时间。读取失败、账号暂不可用或读数超过 15 分钟时，看板胶囊显示「读数 08:30」（琥珀或中性色），不再把旧读数的耗尽预测当成红色告警；额度卡的预测注明来自哪次读数。有页面在看时每 10 分钟记一次读数（打开页面时立即补读，宿主有 5 分钟缓存），最后一次查看 30 分钟后停止，没人看时不让宿主去问厂商；超过 15 分钟没有读数的地方曲线断开。
- **口径**：新输入 + 缓存写入 + 缓存读取 = 模型读入的全部上下文，再加输出就是总量。续接或分叉的会话会复制旧消息，按消息 ID 去重，不会重复计算。只保存计数、模型、工作目录和会话 ID，不保存提示词和输出。不估算费用（同一个模型经不同 Provider、代理或订阅的单价各不相同）。Grok CLI 每轮结束时才记这一轮的用量，所以按轮计入，不参与输出速率、实时流速和「最长的一次输出」；它的输入含缓存读写，已拆开。Pi 计每条回复、带用量的工具结果和压缩 / 分支摘要。

## 复盘（2.6）

会话详情里的「复盘」把整段执行记录在服务端汇总成几张图，客户端只收到几十 KB 以内的摘要；不调用任何模型，和「分析」里的智能分析互补（这里是事实汇总，那边是 AI 点评）：

- **执行时间轴**：每类工作一行（思考、读文件、搜索、改文件、命令、联网、子 Agent、计划、等审批），轮次并排，超过 2 分钟的空闲折叠成虚线；点轮次放大，点色块看这一步的命令、文件、用时和结果。
- **重点**：测试失败几次后通过、连续失败、最慢的命令、长时间思考、等你审批、大改动、提交和推送、派出的子 Agent、上下文压缩、最耗 Token 的一轮。
- **时间都去哪了**：执行用时里思考、命令、改文件等各占多少；几个工具同时跑时按 等审批 › 命令 › 子 Agent › 联网 › 改文件 › 搜索 › 读文件 的顺序只算一次。
- **按轮回顾**：每轮的提问、用时、结果、一条按步骤着色的条码、工具和改动统计、最后的回复。
- **命令与检查、动过的文件、每次模型调用**：测试 / 类型检查 / 代码检查 / 构建 / 依赖安装每次的通过与失败，命令按程序汇总，文件的读写次数和增删行，每次调用的输出、读入上下文和速率。

色块、重点和检查都可以跳到「时间线」里对应的原始记录。

口径：Paseo 宿主只保留合并后的时间线（每个工具一条、只带结束时间），工具的开始时间按它前面最后一条记录估计，同时发出的并行工具共享开始时间；很长的会话只汇总最近 8,000 条（或首次读取累计约 16 MB）记录并在页面上注明；第一次打开时分批读取，每批 500 条。Token 来自同一会话的本地日志，按调用时间归到各轮。

## 并行泳道（2.5）

## 观测（明细 → 观测）

## 智能分析（2.7）

「分析」视图分成「总览」和「报告」，会话详情里的「分析」标签分析单个 Agent。

**谁来分析**（「分析设置」）：
- 新安装默认「自动选择」：主机上找得到 Grok CLI（`PATH` 里的 `grok-cli` / `grok`，或 `~/.grok/bin/grok`，需要已登录）就用它（Grok 4.7 · xhigh）；否则用 Paseo 里已启用的 Claude Code、Codex，再其次是 `extends` 它们的自定义 Provider，用它的默认模型，运行方式和下面手动选 Provider 一样；其他 Provider 不会被自动选用。之前保存过的选择不变。
- Grok CLI：每次在一个新建的临时目录里运行，轨迹摘录写进其中的临时文件交给它。它拿不到任何内置工具（`--disallowed-tools` 列出了全部内置工具），任何工具调用都会被 `--deny "*"` 拒绝，也不使用 Grok 的跨会话记忆和会话搜索（`GROK_MEMORY=0`、`GROK_SESSION_SEARCH=0`）。它只拿到运行需要的环境变量：`PATH`（只留绝对路径）、`HOME`、用户名、语言和时区、临时目录、代理、证书设置和 `GROK_*` / `XAI_*`，daemon 环境里其他 Provider 的密钥不带过去。Grok CLI 会把每次运行存成一份会话（`~/.grok/sessions` 下按目录分组），并把提示词记进会话搜索索引 `~/.grok/sessions/session_search.sqlite`；观测台在分析结束后（成功、失败、取消或超时）立即删除这份会话、临时目录和索引里这次运行的记录（已删除的页覆盖写零，全文索引合并、写前日志清空，一分钟后再查一次）。别的程序正读着这个数据库时写前日志清不掉，删掉的文字可能留在写前日志文件里，直到以后的写入覆盖它（搜索已经搜不到）。插件重载打断分析时留下的残留，在下次启动和启动一小时后清理（一小时内还有更新的会话组不动）。残留按名字认：临时目录下以 `paseo-insight-` 开头的目录都当作观测台的，你自己这样命名的目录和在里面运行的 Grok 会话也会被清掉。Grok 用完轮次仍没给出报告时，用精简证据自动重试一次。选中它之后可以改「Grok 模型」和「推理档」（xhigh / high / medium / low），不填就是 grok-4.7 · xhigh；只在选内置 Grok 时生效，「自动选择」用默认值。
- 也可以选你在 Paseo 里配置的 Profile，或者任意 Provider + 模型 + 思考强度。这时分析会作为被分析会话的子 Agent 在它的工作区里运行，模式总是明确指定，只用两类：只读模式（Codex 及 `extends` 它的 Provider 用只读沙箱，Cursor 的 Ask，各家的 Plan）；没有只读模式时用逐项审批的模式（Claude Code 的 Always Ask），观测台拒绝每个审批请求，但不需要审批的操作（例如读取文件）仍可能执行。不使用可能不经审批就执行的模式（ACP Agent 的 Default / Agent、OpenCode 的 Build 等）：这类 Provider 有 Plan 就用 Plan，没有就不能用来分析；没有列出模式的 Provider 也不能用来分析。Profile 里只保留速度和推理强度一类开关，自动批准之类的开关不会带进分析会话；ACP 和 OpenCode 的分析会话显式关掉自动批准。报告写完就自动归档，可以从报告里「打开分析会话」查看过程，用量计入对应账号；这次对话（含发出的摘录）留在宿主的 Agent 记录和该 Provider 自己的会话日志里（例如 `~/.claude/projects`、`~/.codex/sessions`），观测台不删。它自己读到的文件不经过打码就会发给 Provider。宿主注入给所有 Agent 的工具（例如 Paseo MCP）由宿主设置决定，插件无法单独关闭。
- 会话详情的「更多 → 换个模型分析」只影响这一次，不改设置。

**自动分析**默认关闭（2.7 起，之前保存的开关也会关闭一次），在「分析设置」里手动打开：
- 至少 3 轮用户交互、3 次工具调用，并有足够轨迹或失败信号的任务结束后触发；等待 90 秒，同一会话 6 小时冷却，不批量回填历史。
- 手动分析至少 2 轮、2 次工具调用；支持取消与重试，默认增量跟进新增轨迹与未解决发现，也可完整复盘。

**总览**：近 7 / 30 天（本机时区的自然日）的报告汇总——健康度趋势、问题类型（按严重程度）、待处理的问题、需要关注的 Agent 和项目，都按你在报告里标记的状态（仍存在 / 已解决 / 误判）统计。
- **建议**：让分析模型读一遍最近的报告，找出跨 Agent 反复出现的问题，给出可以直接动手的改进，每条注明收益、投入、类型和依据（点依据跳到对应报告）。「复制指令」得到可以写进 AGENTS.md / CLAUDE.md 的规则；「交给 Agent」在所选项目的工作区用所选 Profile 新建一个 Agent 执行任务（开始前可以改任务内容）；每条建议可以标记采纳、已完成或忽略。开启自动分析后，每积累 3 份新报告（与上次自动建议间隔至少 20 小时）会自动更新建议。
- 报告里的每个发现可以「发给这个 Agent」：把问题和建议作为一条消息发回原会话，由它评估处理（发送前可以修改）。

报告标出执行版本和后续新进展，证据可定位到原始时间线；最新失败/跳过不会遮住已有有效报告，列表只传轻量状态，完整报告按需加载。输入包括有界执行轨迹和项目元数据，可能含代码与业务内容；外发前会遮蔽常见凭据：PEM 私钥、JWT、Bearer 令牌；OpenAI、GitHub、xAI、Groq、AWS（含临时密钥）、Google（API key、OAuth 令牌和客户端密钥）、Slack、GitLab、npm、Hugging Face、SendGrid、Stripe、Composio 等前缀的密钥；password、secret、token、api_key 一类赋值（JSON 再转义一层的也算）；任意协议 URL 里的密码、Slack / Discord webhook，以及 URL 里的 `key` / `sig` / `signature` 参数。每段文字先遮蔽、再截断或转成 JSON；结构化的工具参数和输出里，字段名表明是凭据的（`password`、`AWS_SESSION_TOKEN`、`api_key`、`Authorization`、`credentials` 等）整值遮蔽，转成 JSON 后再遮蔽一遍才截断；模型写回的报告和建议存盘前再遮蔽一次。这不是穷尽脱敏：没有前缀或键名的裸密钥、不到 8 位或带空格的密码会原样发出；数据由所选模型的账号处理。

## 每轮小结与 AI 建议回复（2.17）

新安装默认关闭。在「··· → 观测设置」或「分析设置」的「每轮小结」一节打开；这是宿主设置 `recap`（`$PASEO_HOME/plugin-settings/agent-observatory/recap.json`），所有设备共用一份。

- **什么时候写**：顶层 Agent 的一轮正常结束、安静约 10 秒后写一次（用 Profile / 其他模型写时，同一个 Agent 30 分钟内最多一次）。子 Agent、失败或取消的一轮、以工具调用或报错结束的一轮、正在压缩上下文、有审批或提问在等的都不写；这 10 秒里开始了新的一轮也不写。写之前用宿主的 fetch（不会载入会话）再确认它还空闲、没有在等审批。每个 Agent 每轮最多试一次；全机同时最多写 2 个，其余排队，每个 Agent 只留最新一轮。失败后新的小结暂停 1、2、4… 分钟（最多 30 分钟），写成一次就恢复；找不到 Grok CLI 或所选 Profile 暂时用不了时安静跳过，5 分钟后再看。失败不在会话上提示，设置里能看到原因。
- **写什么**：一句目标和进展（中文约 25 字，英文约 20 个词）和下一步（约 12 字 / 8 个词），用插件当前语言。下一步只取 Agent 问了你还没答的、你们说好的下一步或解决当前卡点的办法，没有就不写；分清提议、已实现、已测试和已上线，不写排查过程和实现细节。
- **在哪显示**：会话列表每行标题下面的 ✦ 彩色行（小结 → 下一步）；详情顶部的「每轮小结」卡片（完整内容、谁写的、多久前）；侧栏「需要处理」弹层每个条目下。新一轮开始后旧小结变灰、标「过时」；正在写新的一份时标「更新中」，✦ 呼吸、卡片底部扫光（系统减少动态效果时静止）。
- **发出什么、发给谁**：这一轮和之前最多 8 轮里你和 Agent 的消息文字（不含工具调用和输出、思考、报错、通知和待办），每条先遮蔽常见凭据（规则同智能分析），再截到约 32 KB：先丢最早的轮次，再给每条留开头和结尾；另附会话标题。只用这一轮结束时宿主交给插件的时间线，不另外读取会话。数据由所选模型的账号处理；遮蔽不保证完整。
- **谁来写**：默认内置 Grok CLI（grok-4.7，`low` 推理档，可在设置里改模型和推理档），隔离和智能分析一样：不给任何工具并拒绝所有调用、环境变量按白名单传、`GROK_MEMORY=0`、`GROK_SESSION_SEARCH=0`，结束后删除临时目录、Grok 存的会话和会话搜索索引里的记录。也可以选 Paseo 里的 Profile 或任意 Provider + 模型：每次小结作为这个 Agent 的只读子 Agent 在它的工作区里运行，写完即归档，用量计入对应账号，这次对话留在宿主和该 Provider 的记录里；为了不让归档的临时子 Agent 越积越多，这时同一个 Agent 30 分钟内最多写一次，只写最新一轮，等待期间旧小结显示「过时」。
- **建议回复**（「顺带生成建议回复」，另一个开关，也默认关闭）：同一次调用里让模型猜你最可能发的下一句（约 2–12 字或 2–12 个词，用你自己的语言和语气）。没把握、Agent 出错或误解了、涉及凭据、删除、强推或生产环境时留空；问句、Agent 口吻、客套、多句、斜杠命令和被遮蔽过的也不显示。它是带「✦ AI 建议」标记的按钮，出现在详情最新回复下的快捷回复区，以及「需要处理」弹层里待回复和未读结果的条目下（审批、提问、计划和停下的条目不给）。点一下才发，原文发出，走插件服务端的发送账本，和快捷回复同一个分组、同一个轮次校验：这一轮已经有快捷回复或建议回复发出，或者 Agent 已经开始新的一轮，就不再发。和规则快捷回复说同一句话（大小写、全半角、空格和标点不计）时只显示规则按钮。
- **存储**：`recaps.json`（见下表），最多 300 个 Agent、30 天；Agent 归档或从宿主目录里消失时删掉；关掉每轮小结时全部删除，关掉建议回复时删掉已存的建议。
- **流量**：会话列表、详情和弹层只在前台显示时读取，每 20 秒一次（有小结正在写时 5 秒），带版本号，未变化时只回几十字节；功能关闭时每分钟一次。界面全部在懒加载分片里，常驻包不变。

## 定时运行（2.9）

侧栏「定时运行」（Command Center 里是「打开定时运行」）列出这台主机上每个 Paseo 定时任务的每一次运行。新建、暂停、修改、立即运行仍在 Paseo 自带的「计划」里做，这里只读。

- **一眼看健康**：顶部是近 7 天的运行次数、失败次数和成功率；「失败 / 执行中 / 成功」标签筛选状态。执行中蓝色转圈并按秒计时，失败红色，成功绿色，只能从 Agent 还原的旧运行是灰色「结果未知」。状态变化时这一行闪一下。
- **按任务看**：每个定时任务一张卡片——最近 10 次运行的色块、计划（每天 09:30、每天 09:00、18:00、工作日 9–18 点每 15 分钟、每月 1 日 09:00、每周一、三、五 09:00、一次性 · 10月11日 22:35）、下次运行时间和失败次数（限次的任务显示第 k/N 次），点一下只看这个任务，顶部随之显示它的名称和近 7 天成绩。手机上卡片横向滑动；宽屏显示一行，其余收在「另外 N 个任务」里。
- **时区提示**：定时任务的时区和设备不同时，计划后面会注明，例如「每天 02:00（UTC）」。没写时区的 cron 由 Paseo 按 UTC 运行。一次性任务在时区和设备不同时，后面写出这台设备上的时间，例如「一次性 · 10月11日 22:35（东京时间）· 本地 09:35」。同时限定日和星期的 cron 原样显示（Paseo 要求两者同时满足）。
- **搜索**：在主机上进行，覆盖任务名、Agent、工作区、分支、错误、链接和完整回复（前 6 万字），不区分全角半角和大小写。
- **运行详情**：定时任务记录的最终回复（标题、列表、引用、代码、加粗和链接都会排版，链接在浏览器打开）、回复里的合并请求（GitLab 式合并请求显示为 `!42`，GitHub PR 显示为 `#128`，已合并为紫色）、「打开会话 / 打开工作区」、提示词和运行信息。失败原因翻译成中文（工作目录已不存在、Agent 在等你审批、daemon 重启、Provider 启动超时、会话无法恢复等），原始错误也能看到。没有记录回复的运行可以「读取会话记录」，只在你点击时读取。
- **心跳默认隐藏**：心跳是定时提醒已有 Agent 的任务，点「心跳」标签或「更多 → 显示心跳」才混进列表，并标出它提醒的 Agent；这台主机只有心跳时直接显示。隐藏后页面写「只有心跳运行（N 次）」，可以一键显示。
- **时间窗口**：先读最近 30 天、最多 200 次运行（另加 100 次心跳），列表底部写明还有多少次更早的运行，「加载更早」最多读 500 + 250 次。
- **删除后仍可查**：Paseo 删除定时任务时会连同运行记录一起删除。观测台为每次运行另存时间、状态、Agent 与工作区 ID、错误（宿主自己的错误信息；失败的一轮只存回复后宿主加的 `[System Error]` 那段，遮蔽凭据，最多 300 字）和链接（去掉 `用户:密码@`），以及任务名称和计划，**不存回复和提示词**（没有名称和标题的任务，列表里临时用提示词开头辨认，账本里只存「未命名定时任务」加短 ID）；观测台在后台记录，不需要先打开页面（监听定时任务目录，每 5 分钟再核对一次，Agent 一轮开始或结束时也补记），所以删除后运行仍在列表里，标为「任务已删除」。2.9 之前就删掉的任务，从 Paseo 给 Agent 打的 `paseo.schedule-id` / `paseo.schedule-run` 标签还原。所属项目已从 Paseo 移除的 Agent 宿主不再列出，观测台改读它们留在 `$PASEO_HOME/agents/` 的记录；宿主打不开这些会话和工作区，详情里会说明。
- **会话里的入口**：被心跳指向的会话带粉色「22:35 唤醒」（暂停的显示「心跳已暂停」），「结果」顶部是心跳卡片：计划、下次唤醒、第几次、上次结果，以及「在定时运行中查看」。到点时 Agent 停在审批上，宿主会把这次运行记为失败，卡片上则是琥珀色「已唤醒 · 提示已送达，Agent 在等你审批」。定时任务创建的会话在「会话」和「已归档会话」里带紫色「定时」徽章，位置不变。详情的「结果」顶部是「定时任务」卡片（任务、计划、这次运行、耗时），「查看全部运行」直接打开这个任务的运行。已归档的会话先显示定时任务记录的回复，不载入会话；需要最初输入、产物和验证证据时再点「读取完整结果」（没有记录可显示时，例如 2.9 之前就删掉的任务，照旧读取会话）。会话读不出来时（ACP 会话无法恢复、日志已删除），「结果」改为显示定时任务记录的回复并说明原因，不再每 30 秒重读，点「重试读取会话」再试。

## 同步与流量（2.1）

为手机弱网和 relay 连接设计，未变化的数据几乎不占用带宽：

- **目录实时推送**：同一主机上同时打开的观测台页面和工作区面板共用一个自有的 Paseo 目录订阅（快照只取 1 条），变化由宿主推送；完整分页读取只在打开、回到前台、断线重连和每 10 分钟校准时发生。订阅不可用时退回每 15 秒读取并自动重试订阅。运行中的 Agent 每次上报用量只原地更新这一行，不触发整表重排；页面其他数据只在状态、提醒、审批、提示词或归档变化时刷新。
- **侧栏角标**：只在侧栏显示且应用在前台时每 20 秒读一次，带版本号，未变化时几十字节；服务端自己持有一个目录观察，没人读时 10 分钟后释放。待办进度和提醒文字只在有会话执行中或等你时每 10 秒读一次；心跳标记每分钟一次；额度每 5 分钟一次（只在 Token / 看板可见时），服务端采样在最后一次查看 30 分钟后停止；续跑状态只在详情显示停下卡片时读取。
- **按版本返回**：观测事件、数据洞察、已读回执、智能分析列表和结果页都带版本号；未变化时只返回几十到两百字节。观测事件变化时只返回新增事件和变化的 Agent 摘要。
- **只取可见内容**：统计只在看板 / 明细 / 横评可见时每 30 秒读取，观测图表只在「明细 → 观测」可见时读取；用量快照只返回图表实际使用的样本。统计快照带版本号，未变化时只返回几十字节。
- **定时运行**：只在页面打开且应用在前台时读取，有运行在执行时每 10 秒、否则每 45 秒；带版本号，窗口边界按 10 分钟移动，未变化时只返回几十字节。单次运行的完整回复在打开详情时才读取，读过的结果本次会话内不再重读。
- **后台即停止**：应用进入 `background` 或 `inactive`（如 iOS 通知中心、来电）时暂停全部轮询、时钟与目录订阅，回到前台立即补齐。
- 执行时间线运行中最多每 5 秒从已缓存的末尾增量读取，输出停下 2 秒或一轮结束时补读一次；在重连后（`subscription_restored`）、会话被替换或手动刷新时才读完整尾部；订阅出错会退避重建，中间缺口不会被静默拼接。结果页运行中每 15 秒刷新；复盘运行中每 30 秒刷新，一轮结束立即刷新；智能分析总览只在显示且在前台时轮询。

## 安装、更新

要求 daemon 与客户端均为 **Paseo `>=0.11.1`**，插件全局开关已启用。插件没有运行时依赖，Paseo 自己编译 TypeScript，安装时不需要构建步骤。

从插件市场或 Git 仓库安装时，在 Paseo 的「设置 → 插件」里填插件来源，或在 daemon 所在的机器上用 `paseo plugin add`。也可以从本地源码安装：

```sh
cd /absolute/path/to/agent-observatory
paseo plugin install "$(pwd)"
paseo plugin ls agent-observatory
```

源码更新后：

```sh
npm run typecheck
paseo plugin reload agent-observatory
paseo plugin logs agent-observatory
```

无需重启 daemon。手机连接同一主机后即可使用侧栏「Agent 观测台」（带需要处理角标）「已归档会话」「定时运行」。Command Center 也提供观测当前工作区/Agent、查看需要处理的会话和打开定时运行，会话里可输入 `/observe`。

## 存储与边界

主机数据目录：`$PASEO_HOME/plugin-data/agent-observatory`。`PASEO_HOME` 只接受绝对路径或 `~/` 开头的路径（读定时任务和写插件数据用同一个规则）；没设、或者是相对路径时用 `~/.paseo`，相对路径会在插件日志里提示一次。目录权限是 0700（已经存在、权限更宽的目录会被收紧），文件是 0600，写入时先写随机名的临时文件再原子替换。

| 文件 | 用途 |
| --- | --- |
| `telemetry.json` | 有界生命周期、用量快照、覆盖区间、项目时间聚合；每个 Agent 最近一轮的停下原因（只有类型和恢复时间）和回复提到的合并请求链接，不存回复 |
| `stats.json` | 看板 / 明细 / 横评的按 UTC 小时聚合（全局小时桶、每个 Agent 每小时的轮次归属、每小时工具计数，保留 92 天，读取时按设备时区换算），以及每个 Agent 的时间线读取位置；有界保留 |
| `quota-history.json` | 额度历史：每个账号（来源 ID + 账号名的哈希，不存账号名原文）各窗口的已用百分比和重置时刻；只在数值变化时记一条，外加每 10 分钟一次心跳；保留 40 天，最多 16 个账号、每个账号 1.2 万条；损坏时另存为 `quota-history.corrupt.json`（只留一份） |
| `tokens.json` | Token 页的按小时 / 按天聚合、会话汇总、日志读取位置和去重索引，有界保留；只有计数，没有内容 |
| `read-receipts.json` | 已读回执及归档清除来源，仅 ID 与时间 |
| `resume-ledger.json` | 恢复后续跑账本：每个 Agent 最近一次续跑的心跳 ID（创建答复丢失、还在核对的为空，核对不了而结束的也为空）、心跳建立（或接管）时的定时规则（cron 和时区）、重试这一次开始的时间（创建答复丢失时按它认领）、原定和当前唤醒时刻、第几次、状态和时间，以及还要删除的续跑心跳 ID（满 200 条先不安排新的续跑，记下的一条不丢；已经开始的安排照样记下，最多 400 条），不存提示或回复；最多 200 个 Agent（在等的续跑从不丢，200 个都在等时先不安排新的），结束后保留 7 天 |
| `deferred-send.json` | 发送账本：快捷回复和「发给这个 Agent」在路上的消息（排队中、发送中、待确认，含正文，最多 100 条、每个 Agent 10 条、最多等一天），以及最近一周的结果（只存前 160 字预览）；定时发送另存到点时刻（UTC），最多排到 7 天后，到点后最多等一天。读不了的账本另存一份备查，最多留 3 份、一周；写到一半中断留下的临时文件在下次启动时删除。发送锁在 `plugin-data/.deferred-send-locks/`（0700，锁文件 0600，记着发给每个 Agent 的消息 ID），和其他插件的账本共用 |
| `sidebar-labels.json` | 侧栏标签：观测台在每个工作区加的标签名、它置顶时宿主记下的置顶时间，以及它新建的标签名；没有别的内容。提醒的开关在宿主的插件设置里（`$PASEO_HOME/plugin-settings/agent-observatory/alerts.json`），「这台设备静音」只在设备上 |
| `device-zone.json` | 读取观测台的设备最近上报的 IANA 时区名（只有这一项），没有客户端在场时按它解析恢复时间、切分后台分析的日期 |
| `preferences.json` | 页面视图、命名视图、按完成版本延后提醒，以及这台主机的观测设置（子 Agent 完成是否计入需要处理） |
| `insight-settings.json` | 独立 AI 配置 |
| `insight-index.json` | 轻量任务、冷却、指纹与版本索引 |
| `insight-reports/` | 单份报告与引用片段，可能包含代码或历史文本 |
| `insight-suggestions.json` | 「建议」任务与你对每条建议的标记；读不了时另存为 `insight-suggestions.json.backup`（只留一份） |
| `recaps.json` | 每轮小结：每个 Agent 最近一份小结、下一步、建议回复（开着建议回复时）、写的时间、它描述的那一轮（插件看到的开始和结束时间）、是否过时、谁写的；最多 300 个、30 天，关掉每轮小结时清空；读不了时另存为 `recaps.json.backup`（只留一份） |
| `schedule-ledger.json` | 定时运行账本：每次运行的时间、状态、Agent / 工作区 ID、错误（只存宿主自己的错误信息或 `[System Error]` 那段，最多 300 字）、合并请求链接（不含 `用户:密码@`），以及任务名称（没有名称和标题时是「未命名定时任务」加短 ID）和计划；不存回复和提示词。最多 3000 次、400 天，有定时任务后才创建 |

Token 页只读本机 Claude Code / Codex / Pi / oh-my-pi / CodeBuddy / Qoder / Qwen Code / Cline / Roo Code / Kilo Code / Hermes / MiMoCode / dsh 的会话日志、Grok CLI 每个会话的 `usage.json` 和 OpenCode 的 `opencode.db` 与 Gemini CLI 的 JSONL 聊天记录（全部只读打开；连同 1.1 时代的 legacy `storage/` 树，见上文「读哪些目录」，含 `$CODEX_HOME/archived_sessions`），以及基于它们的自定义 Provider 的启动脚本文本和 Pi / oh-my-pi 的设置文件；从不写这些文件。升级后第一次启动会对旧版本导入过的 Codex 日志各读一次首行（会话元数据），找出子 Agent 线程属于哪个会话；Grok、Pi、oh-my-pi、OpenCode、CodeBuddy、Qoder、Gemini CLI、Qwen Code、Cline、Roo Code、Kilo Code、Hermes、MiMoCode、dsh 的历史在升级后导入一次。智能分析结束后删除 Grok CLI 为它存的会话（只删观测台自己临时目录对应的那一组）和会话搜索索引里这次运行的记录（只读记录的目录、编号和时间，不读内容）。恢复后续跑核对是否送达时，观测台会读这个 Agent 自己的会话日志（Claude Code / Codex / Pi）：最多 4 个文件，只比对这次心跳和运行的编号（`fired (id=<心跳>, run=<运行>)`），不解析、不保存。运行中每个文件只读末尾最多 16 MB，最多每 2 分钟查一次、只查前半小时；下结论时不为它另外扫描、也不排队等待，用平时扫描的结果，把每个文件从头读到尾（最多 128 MB），读完核对文件没有变化。Grok 的会话从不打开。

观测台写入 Paseo 的操作都要你点按、需要时先确认：发消息（「发给这个 Agent」、快捷回复、AI 建议回复）、就地审批（`respondToPermission`，按你选的选项原样回复）、标记已读 / 知道了（清除宿主提醒）、归档与恢复会话、新建 Agent（「交给 Agent」「交给另一个 Provider」），以及「恢复后续跑」：通过宿主自己的 `schedule/create` 请求建一次性心跳（和 `paseo heartbeat create` 相同）。定时发送在你选的时间发出；「侧栏标签」打开后，观测台自己写工作区标签和置顶，只动它自己加的。续跑没送出时观测台会替换成新的一条；「取消续跑」、被替换或续跑结束时，只删这个 Agent 自己的一次性续跑心跳（名称以「恢复后续跑」开头、只运行一次、提示是续跑提示，`schedule/delete`）；每次核对、重试、接管和删除前都按宿主当前的记录重新核对，你在 Paseo 里改过的就不再碰。打开每轮小结（或自动分析）并选了 Profile / 其他模型时，观测台会自己建一个只读子 Agent 写小结（同一个 Agent 30 分钟内最多一次），写完即归档。

定时运行只读 `$PASEO_HOME/schedules/*.json`（单个文件超过 32 MB 跳过）、`projects/workspaces.json`，以及宿主不再列出的 Agent 的记录 `agents/<目录>/<id>.json`（目录每分钟最多列一次，文件变了才重读，超过 1 MB 跳过），按修改时间缓存，从不写回 Paseo 的文件。每次扫描最多读 2000 个定时任务文件（合计 256 MB）、5 万个 Agent 记录（合计 256 MB、10 万个目录条目），超出的部分跳过，页面上会提示。账本损坏或超过 8 MB 时另存为 `schedule-ledger.corrupt.json`（只留一份，下次损坏时替换）并重新记录；读不了时本次不改写它，只显示宿主现有记录；保存失败会在页面上提示。

旧版本 AI 历史会迁移并保留备份。设置与大报告分离，配置恢复异常时自动分析保持关闭。报告有单份和总字节上限。

写盘策略：生命周期事件在 250 ms 内原子写入并 fsync；仅心跳覆盖区间变化时最多每 10 分钟写一次且不 fsync；与上次写入完全相同的内容不重写。智能分析索引只在内容变化时重写，Agent 轮次计数延迟 30 秒合并保存。

目录优先加载需要关注的任务，再读取普通最近会话；超出容量明确显示已加载/截断。时间线与报告也是有界缓存，不声称保存了提供方未上报或已删除的历史。

Paseo 原生清除已读仍没有原子版本条件。插件继续逐条校验和复查，不提供盲目批量清除，也不声称插件能实现上游 CAS。原生子任务、工作区恢复、会话刷新与清除已读使用现有插件 IPC 会话的兼容适配（PaseoApi 仍未提供）；宿主因心跳租约过期重建插件会话时，进行中的请求立即失败并提示重试，新请求等会话重新接入后再发送。升级 Paseo 主版本前需重新验证。

# Kimi Code and ZCode token sources

This extension changes Agent Observatory only. It reads local provider history and does not run agents, modify provider configuration, call billing APIs, or write provider databases/logs.

- Kimi Code: `$KIMI_CODE_HOME/sessions` (default `~/.kimi-code/sessions`), `session_*/agents/*/wire.jsonl`, and the session's `state.json` for cwd. Only `usage.record` contributes tokens. `inputOther` is fresh input; cache reads/creation are separate. Subagents share the parent session id and retain their subagent flag. Request timestamps supply response duration. Negative counters from provider logs are clamped to zero, consistently with other sources.
- ZCode: `$ZCODE_HOME/cli/db/db.sqlite` (default `~/.zcode/cli/db/db.sqlite`). A read-only SQLite connection includes committed WAL records. Only `step-finish` counters count; the duplicate assistant-message totals do not. Its input includes cache, so cache read/write counts are subtracted before adding fresh input. Fork history whose request predates the child session is excluded. `subagent_child` sessions are identified separately from forks.
- Paseo Kimi sessions use their native `session_` id. ZCode plugin envelopes are unwrapped and mapped using `v2/acp-lazy-sessions.json` under the provider's discovered home, the daemon's `ZCODE_HOME` or the standard home. Custom providers are identified from their actual daemon definitions, using the same command and home discovery as token roots; their display names are not guessed. Bridge metadata is read asynchronously through a bounded reader. Each service owns its cache and coalesces concurrent reads; home, environment, clock and reader can be supplied in tests. A missing mapping remains unmatched rather than guessing from titles or working directories.

The ledger retains counters, model, timestamps, session ids and cwd, not prompts or outputs. Kimi resumes at the JSONL byte offset; ZCode resumes at the part rowid and detects WAL changes even when the main database file is unchanged. Its cursor also records a hash of the last part id: a primary-key lookup detects rowid reuse after history deletion, and only then resets the import with stable-id deduplication. Execution reviews use the session table's primary key when a session is absent from the bounded checkpoint index, so newer sessions remain accessible. Provider schema/read failures appear as coverage errors. Node's `node:sqlite` is required for ZCode (verified on this host's Node 24); failure affects that source rather than silently reporting zero.

ZCode reads completed append-only steps. Editing the counters of already imported historical steps in place is not a supported provider workflow; a fresh ledger/import is needed after such manual edits. Deleted history cannot be reconstructed. Token counts are not monetary costs or remaining subscription allowance. Unmatched terminal/desktop sessions remain included, as in the original plugin.

Validation includes isolated WAL-only appends, restart cursors, per-agent history isolation, fork exclusion, cache arithmetic, Kimi subagents/partial lines, unchanged provider DB/WAL bytes, bridge mappings, unsupported database schemas, and the existing token tests.

Ferry moves a Paseo conversation to another provider, and back again. When a quota runs out, a route stops connecting or another model suits the next step better, press "⇄ Ferry" by the composer, type `/ferry` with the provider you want, or pick one in the Command Center ("Ferry: continue with another agent…"). The conversation carries on there, in the same workspace.

For every move Ferry picks the best way across and shows it before anything happens:

- **Same session.** When both providers run the same CLI on the same session store (for example two Claude Code providers that both use `~/.claude`), the target imports the very same session: every message, tool result and thought. Nothing is summarized, and nothing is sent unless you write. Custom providers count.
- **Switch back.** When an agent on the target already had this conversation, it comes back and gets only what happened while it was away. Its own context is still there.
- **Handoff.** Anywhere else, a new agent gets the conversation's history as text along with your message, chosen to fit a budget.

A route that fails part-way falls back to a handoff and says why. The previous agent is archived (or kept, if you prefer), and a row in each chat records the move, with a link back and, for handoffs, exactly what was sent.

**What a handoff carries.** Messages, plans, the latest to-do list, commands with exit codes and the start and end of their output, a line per turn for files edited, read or searched, errors and notices; no hidden reasoning or raw tool results. The latest request and reply, the original request and the to-do list always go in, then the newest items that fit. The budget is 16k tokens by default, less when the target's context is small or already full. API keys, bearer tokens, private keys and passwords in URLs are redacted first. The history travels as a Paseo chat history attachment, as with Paseo's own Fork: the model reads it before your words as context, not instructions, and your message bubble shows only what you wrote.

To let the next agent look further back, each handoff writes the full, redacted history to a file and names it, and where Paseo gives agents its MCP tools, agents in a chain get a read-only `ferry_read_history` tool: pages, single items and search over the whole conversation, numbered as in the handoff.

**The picker** groups providers by route and shows the model, permission mode and thinking level the next agent will use, how much history fits, and a preview of the exact text. Ferry never makes the next agent more permissive: it keeps the mode or maps it by tier (plan, ask, edit, full access), and warns when nothing on the target is as careful.

**Partners** make it one step: set `provider-a → provider-b`, and `/ferry` with no target or the composer button goes straight there; after a failed turn the button says so ("Out of quota → provider-b"). When a reply is itself a quota notice or a provider error, Ferry adds a row with the same way out. Ferry never switches on its own.

**Settings** (Settings → Plugins → Ferry) cover partners, the budget, command output, the default message, archiving, native continuation and each provider's session store, the history tool and record file, the composer button and quota rows, delivery for providers that drop attachments, retention, and a slash alias such as `/switch`. The screens are in English and Simplified Chinese; a command-line tool works from a terminal.

**What it reads, writes and sends.** Ferry reads the timelines of the agents you move, and at the end of each turn that turn's rows, to spot a reply that is a quota notice or a provider error (unless those rows are off). From Paseo it reads the providers and models, and from their configuration only the session store variables (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`); the picker shows each store's directory. Before continuing a session natively it looks for the session's file in the store, and for an agent the daemon cannot load it reads Paseo's own record under `$PASEO_HOME/agents/`. It writes under `$PASEO_HOME/plugin-data/ferry/`: which agents each conversation passed through, the items of each finished stretch, the text each handoff sent and the record files, private to your user (directories 0700, files 0600), plus a `locales/` folder for your own translations. Conversations untouched for 30 days are forgotten with their files; the settings can forget everything at once. History goes only to the agent you move the conversation to, through Paseo. Ferry makes no network requests and starts no processes.

**Native continuation uses Paseo internals.** Paseo's plugin API cannot import a session or stop a turn yet, so for these Ferry opens a second connection to the same local daemon with Paseo's own client and the daemon's local credential, as the `paseo` CLI does. With native continuation off, it connects only to stop a turn you asked it to stop, and every move is a handoff.

**Limits.** After a daemon restart, or in an imported session, some providers replay a handoff joined to the user's words, so that bubble shows the history block, collapsed, as with Paseo's Fork. Whether an agent gets the history tool depends on its provider. Native continuation across different backends behind one CLI needs the backend to accept the other's history; if one refuses, mark its store "not shared". Installing or reloading Ferry reopens open agent sessions once, because the tool is attached when a session opens.

**How it differs.** Switch provider and Continuity start a new agent on every switch. Ferry returns to agents that already had the conversation with only what they missed, continues the same session wherever providers share a store, and keeps a numbered, searchable record for whoever takes over.

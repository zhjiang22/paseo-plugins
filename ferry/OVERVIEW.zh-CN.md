摆渡（Ferry）把 Paseo 里的一段对话交给另一个 Provider 接着做，之后也能再切回来。额度用完、线路不通，或者下一步更适合换个模型时，点输入框旁的「⇄ 摆渡」，或在输入框里输入 `/ferry` 加上目标 Provider，或在命令面板里选「摆渡：换一个 Agent 接着聊…」。对话会在同一个工作区里接着进行。

每次换过去之前，摆渡都会先选好走法并展示给你：

- **同一个会话（原生续接）**：两个 Provider 用同一个 CLI、共用同一个会话存储时（比如两个都用 `~/.claude` 的 Claude Code Provider），目标直接导入同一个会话，所有消息、工具结果和思考过程都在，没有任何摘要。你不写消息就什么都不发。自定义 Provider 同样适用。
- **切回**：目标上已经有一个参与过这段对话的 Agent 时，就回到那个 Agent，只补它离开期间发生的事。它原来的上下文都还在。
- **交接**：其他情况下，新开一个 Agent，把对话历史按预算挑选后，和你的消息一起发过去。

某条走法中途失败时，会退回交接，并说明原因。原来的 Agent 默认归档（也可以设为保留）。两边的对话里各加一行记录，可以一键切回；交接的记录还能查看当时发出的原文。

**交接带什么**：消息、计划、最新的待办、命令及其退出码和输出的开头结尾，每轮改了哪些文件、看了或搜了什么各一行，以及错误和通知。隐藏的思考过程和原始工具结果不带。最后一条请求、最后一条回复、最初的请求和待办一定会带上；然后从新到旧放进放得下的条目，放不下的跳过、接着往前。预算默认 16k token，目标上下文较小或快满时会自动缩小。API 密钥、Bearer token、私钥和 URL 里的密码会先脱敏。历史作为 Paseo 的「对话历史」附件发送，和 Paseo 自带的 Fork 用的是同一种：模型先读到它，并被告知这是背景而不是新指令；你的消息气泡里只显示你自己写的话。

接手的 Agent 还能往回翻。每次交接都会把完整历史（已脱敏）写进一个文件，并在交接里告诉对方路径；Paseo 向 Agent 提供 MCP 工具时，链上的 Agent 还会拿到只读的 `ferry_read_history` 工具，可以分页、按编号读单条或搜索整段对话，编号和交接里的一致。

**选择页**按走法分组，显示接手 Agent 会用的模型、权限模式和思考档位、能放下多少历史，并能预览要发出的原文。摆渡不会让接手的 Agent 权限变得更宽：同名模式直接沿用，否则按档位（规划、询问、编辑、完全放开）对应；目标没有同样谨慎的模式时会提醒你。

**搭档**让切换只需一步：设好 `provider-a → provider-b` 后，不带目标的 `/ferry` 和输入框旁的按钮都会直接切过去；某轮出错后，按钮会写明原因（「额度用完 → provider-b」）。如果某条回复本身就是额度提示或 Provider 报错，摆渡会在对话里加一行，提供同样的出路。摆渡从不自动切换。

**设置**（设置 → 插件 → 摆渡）包括：搭档、预算、命令输出、默认消息、交接后是否归档、原生续接和各 Provider 的会话存储、读历史工具和完整记录文件、输入框旁的按钮和额度提示行、对不收附件的 Provider 改为直接写进消息、保留天数，以及斜杠命令别名（比如 `/switch`）。界面支持英文和简体中文。另附一个命令行工具，可以在终端里做同样的操作。

**读写和发送了什么**：摆渡会读取你要换走的 Agent 的对话记录；每轮结束时还会读这一轮的内容，看回复本身是不是额度提示或 Provider 报错（这类提示行可以在设置里关掉）。它读取 Paseo 报告的 Provider 和模型，以及 Paseo 的 Provider 配置，其中只用到会话存储相关的变量（`CLAUDE_CONFIG_DIR`、`CODEX_HOME`），选择页会显示各自的存储目录。原生续接之前，它会确认会话文件确实在存储里；遇到 daemon 加载不了的 Agent（比如它的 Provider 被关掉了），它会读 Paseo 自己在 `$PASEO_HOME/agents/` 下保存的这个 Agent 的记录。它把数据写在 `$PASEO_HOME/plugin-data/ferry/` 下：每段对话经过了哪些 Agent、每段结束时的条目、每次交接发出的原文和完整记录文件，目录只有你本人可读（目录 0700，文件 0600）；另有一个放你自己翻译的 `locales/` 目录。30 天没有动静的对话记录会连同文件一起删除，设置里也能一次全部清除。历史只会通过 Paseo 发给你选择的那个 Agent。摆渡不发起网络请求，也不启动任何进程。

**原生续接依赖 Paseo 的内部接口**：Paseo 的插件接口目前还不能导入会话，也不能停止正在运行的一轮，所以原生续接时，以及你让摆渡先停掉正在运行的一轮时，摆渡会用 Paseo 自己的客户端和 daemon 的本机凭据，再开一条到同一个本地 daemon 的连接，方式和 `paseo` 命令行一样。关掉原生续接后，摆渡只在你让它停掉正在运行的一轮时才建立这条连接，换 Agent 一律改走交接。

**已知限制**：daemon 重启后，或在导入的会话里，部分 Provider 重放消息时会把交接内容和用户的话拼在一起，所以那一条气泡里会显示历史块（默认折叠）。Paseo 自带的 Fork 也是这样；摆渡不会让历史块层层嵌套。接手的 Agent 能否拿到读历史工具取决于它的 Provider。同一个 CLI 背后接不同厂商后端时，原生续接取决于后端是否接受对方留下的历史；如果不接受，把它的会话存储设为「不共享」即可。安装或重载摆渡时，已打开的 Agent 会话会重开一次，因为读历史工具是在会话打开时挂上的。

**和其他插件的区别**：Switch provider 和 Continuity 每次切换都新开 Agent。摆渡能回到参与过对话的 Agent，只补它错过的部分；凡是共用会话存储的 Provider 都能原生续接；并为接手的 Agent 保留一份带编号、可搜索的完整记录。
